# Gemini Code Review Instructions

## Purpose

Use this document to ask Gemini, or another external reviewer, to review the recent LEBE product feed and product page work without making changes. The review should be read-only and should focus on bugs, regressions, catalog disapproval risks, checkout risks, analytics pollution, and scalability issues.

## Reviewer Role

You are reviewing the LEBE website repository. Do not modify files. Do not reformat code. Do not propose broad rewrites unless a concrete bug or maintainability risk requires it.

Produce findings first, ordered by severity. Every finding must include:

- File path
- Line number or narrow code reference
- Why it is a problem
- What could break
- A concrete recommended fix

If no blocking issues are found, say that clearly and list remaining risks or test gaps.

## Project Context

LEBE is a static-first ecommerce site deployed on Vercel. The product catalog currently has four public products:

- Saguanari White Leggings: `/product/saguanari-white-leggings`
- Saguanari White Sports Bra: `/product/saguanari-white-sports-bra`
- Saguanari Black Leggings: `/product/saguanari-black-leggings`
- Saguanari Black Sports Bra: `/product/saguanari-black-sports-bra`

Each product has five size variants: `XS`, `S`, `M`, `L`, `XL`.

The recent work made `src/js/product-data.js` the source of truth for product feed generation. The build now emits:

- `src/products-feed.xml` for Google Merchant Center
- `src/products-feed-meta.xml` for Meta Commerce Manager

Both feeds should be generated by `scripts/build-html.js` from the same product metadata. They should not be hand-maintained.

## Non-Negotiable Constraints

- Do not change existing product item IDs.
- Do not change product slugs.
- Do not change prices unless there is clear evidence the source price is wrong.
- Do not remove `g:quantity_to_sell_on_facebook`.
- Do not collapse product variants into one item.
- Do not add fake reviews, ratings, GTINs, or MPNs.
- Do not reintroduce Printful as the feed generation source.
- Do not break Google feed compatibility while fixing Meta feed compatibility, or vice versa.
- Do not hardcode XML manually; the source of truth should remain `src/js/product-data.js`.
- Keep the site static-first and compatible with Vercel Hobby limits.
- Build output should not require network access or secrets such as `PRINTFUL_API_KEY`.

## Core Feed Review

Review `src/js/product-data.js`, `scripts/build-html.js`, `src/products-feed.xml`, and `src/products-feed-meta.xml`.

Verify:

- `products-feed.xml` is generated from `src/js/product-data.js`.
- `products-feed-meta.xml` is generated from `src/js/product-data.js`.
- There are exactly 20 items in each feed.
- There are four distinct `g:item_group_id` values.
- Each `g:item_group_id` has exactly five items.
- Every item has `g:size`.
- Every item has `g:color`.
- Every item has `g:price`.
- Every item has `g:availability`.
- Every item has `g:image_link`.
- Every item has `g:identifier_exists`.
- Every item has `g:item_group_id`.
- Every item has a slug-based `g:link` on `https://www.lebe.life`.
- No feed item links to `/product?id=...`.
- No feed item links through redirects.
- No feed item emits `g:mpn`.
- No feed item emits `g:gtin`.
- `g:identifier_exists` is `no`.

## Google Feed Rules

- It does not use `in stock`.

- Product links use `https://www.lebe.life/product/<slug>`.
- `g:google_product_category` is valid and XML-escaped.
- `g:product_type` is merchant-facing and consistent by product type.

## Meta Feed Rules

For `src/products-feed-meta.xml`, verify:

- `g:availability` is exactly `in stock` on all 20 items.

- The feed is otherwise identical to the Google feed.
- `g:quantity_to_sell_on_facebook` remains present.
- Item IDs match the Google feed.

- Links, images, prices, sizes, colors, titles, and descriptions match the Google feed.

- Feed image is the same primary PDP image.

- No old `/product?id=...` URLs remain in sitemap, canonical tags, Open Graph tags, or structured data.

## Accessibility And UX Review

Review product page interactions and newsletter-related copy.

Verify:

- Product images have useful alt text.
- Size selector exposes selected state.
- Color selector exposes selected state.
- Gallery controls are keyboard accessible.
- Size guide modal can be opened, closed, and focused predictably.
- Add-to-cart controls are reachable by keyboard.
- Cart controls have useful labels.
- Newsletter confirmation copy directs users to check email and does not reveal the coupon code.

## Scalability Review

Look for assumptions that would break when adding a fifth product or a new product category.

Flag:

- Hardcoded product counts outside tests.
- Hardcoded four-product assumptions in feed generation.
- Hardcoded size assumptions that cannot support future products.
- Duplicated product copy or price data outside `src/js/product-data.js`.
- Hidden Printful-only assumptions in static feed generation.
- Dead code left behind by the feed refactor.
- Any path where a future product could appear on the site but not in the feed, or in the feed but not on the site.

## Output Format

Use this structure:

```text
Findings

1. [Severity] Title
   File: path:line
   Problem:
   Impact:
   Recommended fix:

Open Questions

- Any assumptions that need confirmation.

Validation Performed

- Commands run and results.

Summary

- Brief statement of whether the change is safe to ship.
```

Severity levels:

- Blocking: likely to break checkout, deployment, feeds, indexing, or catalog approval.
- High: likely to cause bad data, broken product pages, or significant merchant/analytics issues.
- Medium: meaningful risk but not immediately launch-blocking.
- Low: cleanup, maintainability, or minor UX/accessibility issue.
